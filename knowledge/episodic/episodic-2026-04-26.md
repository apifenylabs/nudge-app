## Evening Extended — "0 Destinations" Bug Fixed (22:39-23:10 HK)

**Time:** 22:39-23:10 HK
**Channel:** Telegram — Alpha Orchestras HQ (topic #2)
**Budget:** Under $0.15, DeepSeek-chat only.


## The bug
- Landing page rendered "0 destinations" in SSR HTML despite having 506 destinations in JSON and RSC data
- Root cause: In Next.js App Router, client component props from server components are NOT available during SSR HTML render — they're only hydrated from the RSC payload stream
- The `useState(meta?.totalDestinations || 0)` initialized to 0 on the server because `meta` prop wasn't available during SSR
- Multiple fix attempts: script tag injection, ssrDestinations prop, getStaticProps — all produced correct RSC data but empty SSR HTML


## The fix
- Changed `HomeContent` to accept `meta` as a direct prop: `HomeContent({ meta }: { meta: MetaData | null })`
- Client component initializes from the prop: `const [totalDestinations, setTotalDestinations] = useState(meta?.totalDestinations || 0);`
- Server component renders: `<HomeContent meta={getMeta()} />`
- This works because passing a server-computed object directly to a client component's props makes it available during SSR in this version of Next.js — the `meta` object gets serialized into the RSC payload AND the SSR HTML via prop drilling


## Verification
- 4 deploy attempts before the fix worked (script tag → ssrDestinations prop → remove prop → direct meta prop)
- Final commit: `[master 573d598] fix: pass meta directly as client component prop for SSR`
- **Verified live:** SSR HTML now shows "506 destinations" in header, "506 hand-picked destinations" in hero, "506+" in stats section, "230 cities", "2482+ tips"
- HTML diff proof: `<span id="dest-count">506 destinations</span>` in final vs `<span id="dest-count">0 destinations</span>` before

## Evening Extended — "0 Destinations" Bug Fixed (22:39-23:10 HK)

**Time:** 22:39-23:10 HK
**Channel:** Telegram — Alpha Orchestras HQ (topic #2)
**Budget:** Under $0.15, DeepSeek-chat only.


## The bug
- Landing page rendered "0 destinations" in SSR HTML despite having 506 destinations in JSON and RSC data
- Root cause: In Next.js App Router, client component props from server components are NOT available during SSR HTML render — they're only hydrated from the RSC payload stream
- The `useState(meta?.totalDestinations || 0)` initialized to 0 on the server because `meta` prop wasn't available during SSR
- Multiple fix attempts: script tag injection, ssrDestinations prop, getStaticProps — all produced correct RSC data but empty SSR HTML


## The fix
- Changed `HomeContent` to accept `meta` as a direct prop: `HomeContent({ meta }: { meta: MetaData | null })`
- Client component initializes from the prop: `const [totalDestinations, setTotalDestinations] = useState(meta?.totalDestinations || 0);`
- Server component renders: `<HomeContent meta={getMeta()} />`
- This works because passing a server-computed object directly to a client component's props makes it available during SSR in this version of Next.js — the `meta` object gets serialized into the RSC payload AND the SSR HTML via prop drilling


## Verification
- 4 deploy attempts before the fix worked (script tag → ssrDestinations prop → remove prop → direct meta prop)
- Final commit: `[master 573d598] fix: pass meta directly as client component prop for SSR`
- **Verified live:** SSR HTML now shows "506 destinations" in header, "506 hand-picked destinations" in hero, "506+" in stats section, "230 cities", "2482+ tips"
- HTML diff proof: `<span id="dest-count">506 destinations</span>` in final vs `<span id="dest-count">0 destinations</span>` before
