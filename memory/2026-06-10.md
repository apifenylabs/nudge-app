## 2026-06-10 ~08:00-13:00 HKT — Silent Strategy Failure Bug: Zero Signals Since Deploy

### Bug Discovery & Root Cause
- **From Jun 7 23:10 deploy through Jun 10 08:00: ZERO signals across all 6 strategies**
- CEO noticed via Aqua Pulse cron report saying "live_execution=false" and "guard not configured"
- **Root cause:** `dc.get_price(coin)` returned `None` for some coins (data connector returns None on API miss). Orchestrator at line 315: `current_price = dc.get_price(coin) if dc else 0.0` — fallback only when `dc` is falsy, not when `get_price()` returns None. All strategies crashed on `None > 0` comparison. `run_strategy()` caught the exception and returned None. Zero signals for 3 days.
- **Secondary issue:** `status()` returned `guard_layer: {}` and `live_execution: false` because guards are lazy-initialized (only on first cycle). Pulse agent read this and wrote "not configured" for everything.

### Fixes Applied (4 changes + cron cleanup)
1. **`orchestrator.py` — `status()`**: Now returns full guard status with descriptive states ("inactive — no signal yet") instead of empty dict when guards are uninitialized. Reads `config.PAPER_MODE` for accurate `live_execution` flag.
2. **`orchestrator.py` — `status()`**: Added `paper_mode` field for easy checking. Added data connector + price feed health check.
3. **Queue cleanup**: Cleared 6 stale paper orders from the bug era still sitting in trade_registry.json
4. **4 cron jobs updated**:
   - `trading-pulse-30min` → `aqua-pulse-30min` (uses orchestrator status, not pulse_bot)
   - `morning-pulse-telegram` → `morning-aqua-pulse` (uses orchestrator status, labels accurate)
   - `trading-beast-daily-report` → `legacy-daily-report` (silent mode, archive pending)
   - `trading-audit-daily` → `aqua-audit-daily` (uses orchestrator health, not audit_agent)

### Current State (13:00 HKT)
- `status()` now returns: `paper_mode: false`, `live_execution: true`, guard layers with proper labels
- Queue: 0 pending, 0 completed (clean — old stale entries cleared)
