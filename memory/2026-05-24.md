## 🔴 CRITICAL — Hyperliquid Fix (THIS SESSION)

### The Bug
The old `hyperliquid_connector.py` was querying `clearinghouseState` (perp clearinghouse) which returned $0. It had a fallback that silently returned paper defaults (`STARTING_CAPITAL=41`). So for days the bot reported "$41 balance" and "6 trades" — but it was NOT actually trading live. The SDK's `Info` class's `user_state()` also returns perp-side data.

### The Fix (THIS SESSION, confirmed working)
**Never use `clearinghouseState` or `user_state().marginSummary.accountValue` alone.** The $41 USDC is in the **spot wallet** (`spotClearinghouseState` → `balances[USDC].total`). For **unified accounts** (which HL has since v0.23), you must read the **portfolio endpoint**:

- ✅ `Info.portfolio(wallet_address)` → `[0][1]["vlm"]` — gives the **total unified account value**
- ✅ Fallback: `Info.spot_user_state(wallet_address)` → `balances[USDC].total`
- ✅ **NEVER** rely on `clearinghouseState` for balance — it only shows perp wallet
- ✅ **NEVER** use paper defaults as fallback — this caused false confidence

### SDK Authentication
- Private key (64 hex chars, no 0x prefix) → `Account.from_key(pk)` → wallet address
- `Exchange(wallet, base_url="https://api.hyperliquid.xyz")` for trading
- `Info("https://api.hyperliquid.xyz", skip_ws=True)` for data
- The `usd_class_transfer` returns "Action disabled when unified account is active" — that's OK, unified accounts don't need transfers
- `order("SOL", ...)` returns price/divisible tick error if Price is not rounded to tick size
- Market orders: use `market_open()` or `order(..., {"limit": {"tif": "Ioc"}})`
- TP/SL groups: `place_tpsl_group` works but needs proper size rounding per asset's `szDecimals`
