## Gateway Fix: Paperclip ↔ OpenClaw Gateway Auth

**Root Cause Found (3 issues):**
1. **`client.mode: "operator"`** → Paperclip adapter was sending `mode: "operator"` (the role value). The gateway schema requires a literal string matching `GATEWAY_CLIENT_MODES.*`. Valid modes: `"webchat"`, `"cli"`, `"ui"`, `"backend"`, `"node"`, `"probe"`, `"test"`. Both `"cli"` and `"backend"` work.
2. **Signature payload format wrong** — The gateway doesn't just sign the nonce. It signs a structured V3 payload: `"v3|deviceId|clientId|clientMode|role|scopes|signedAtMs|token|nonce|platform|deviceFamily"`. My early test was only signing the nonce.
3. **Device identity** — `deviceId` is NOT arbitrary. It's SHA-256 of the raw 32-byte Ed25519 public key point.

**Three correct attempts approach:**
- Attempt 1: Found `GATEWAY_CLIENT_MODES.CLI = "cli"` in message-channel-BzmQarxU.js — switched mode from "operator" to "cli" ✅ passed schema validation
- Attempt 2: Added proper Ed25519 keypair derived from Paperclip's private key, computed `deviceId = sha256(raw_key)`, used base64url encoding for publicKey/signature — passed device identity ✅
- Attempt 3: Implemented `buildDeviceAuthPayloadV3` signature format — **CONNECT SUCCESSFUL** ✅

**Paperclip adapter file found:**
`@paperclipai/adapter-openclaw-gateway/dist/server/execute.js`
- Defaults: `DEFAULT_CLIENT_ID = "gateway-client"`, `DEFAULT_CLIENT_MODE = "backend"`
- Accepts config overrides: `ctx.config.clientId`, `ctx.config.clientMode`
- Auto-generates ephemeral keys when `devicePrivateKeyPem` not set

**Fix applied:** Updated all 11 Paperclip agents with `clientId: "cli"` and `clientMode: "cli"` in adapter config via PATCH API.

**Device paired:** Paperclip CEO device (key derived from private key in adapter config) now registered with gateway.
