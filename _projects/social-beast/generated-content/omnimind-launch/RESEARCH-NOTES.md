## Key Findings Applied to These Drafts

### Product Hunt
- Old approach: "submit at midnight PT, ask friends to upvote" — this is dead in 2026
- New approach: 4-6 week prep with narrative building, real comment engagement, post-launch 30-day sprint
- Algorithm rewards: comment quality > upvote velocity. Spam patterns = penalized.
- Top 5 threshold: 200-350 upvotes depending on launch day competition
- Conversion targets: 15-25% visit→signup, 35-45% signup→activated within 7 days
- Best days: Tuesday-Thursday. Avoid Monday (low) and Friday (weekend drop).

### Twitter/X Threads
- Thread format is the most efficient distribution channel for complex dev tool ideas
- Hook tweet must stop scroll — specific, counterintuitive, or high-value claim
- 8-12 tweets max. Longer threads bleed engagement.
- Bookmark rate is the strongest quality signal (drives algorithmic amplification)
- Framework threads, build-in-public, and "I built X" perform best for dev tools
- Each tweet must earn its place — no padding
- Closer: TL;DR summary + CTA + "RT the first tweet so others find it"

### Reddit
- r/openclaw: technical audience, familiar with the pain point, skeptical of self-promo
- r/AI_Agents: technically sophisticated, wants honest tradeoffs, not feature lists
- r/SideProject: loves "how I built this" with specific problems encountered
- Key pattern for all: lead with problem, be honest about limitations, include code link
- "Upvote if you agree" = instant downvote territory

### Voice/Tone Rules Applied
- No "revolutionary," "game-changing," "cutting-edge," "disruptive"
- Problem-first, not "I built X" — "Agents forget everything" before "here's my tool"
- Specifics before adjectives — "3 embedded databases" > "multi-modal architecture"
- Honest about what's NOT solved — builds credibility
- Short sentences. One idea per tweet/post. No padding.
