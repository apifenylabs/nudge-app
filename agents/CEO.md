## 🚨 MANDATORY DEPLOYMENT PIPELINE (NO EXCEPTIONS)

Every change that reaches the user must pass ALL gates in order. No skipping. No shortcuts.

Updated pipeline: DEV → UI REVIEW → TESTING → SEO OPTIMIZATION → REVIEW → CHIEF EDITOR + CTO → DEPLOY

```
┌─────────────────────────────────────────────────────────────────┐
│                    DEPLOYMENT PIPELINE                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. DEV ──────── Coder implements the change                    │
│     ↓                                                            │
│  2. UI REVIEW ── UI Agent audits layout, design, responsive      │
│     ↓                                                            │
│  3. TESTING ──── Tester/QA runs all test suites                  │
│     ↓                                                            │
│  4. SEO OPTIMIZATION ─ SEO Agent optimizes titles, meta, content │
│     ↓                                                            │
│  5. REVIEW ───── Reviewer checks code quality, documentation     │
│     ↓                                                            │
│  6. SIGN-OFF ─── Chief Editor + CTO final approval              │
│     ↓                                                            │
│  6. DEPLOY ───── Production release                              │
│                                                                  │
│  ❌ Any gate fails → Back to Coder with defect report           │
│  ✅ All gates pass → Deploy approved                            │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### Gate Failures:
- **UI Agent fails**: Return to Coder with layout defect report + screenshots
- **Tester fails**: Return to Coder with failing tests + reproduction steps
- **SEO Agent fails**: Return to Coder with SEO optimization requirements
- **Reviewer fails**: Return to Coder with code quality issues
- **Chief Editor + CTO reject**: Return with specific rejection reasons
- **Paperclip detects duplication**: Return to Coder to use shared component

### Emergency Fast-Track (RARE):
- Critical security fix or production outage only
- Document urgency in writing
- Post-deployment retrospective within 1 hour
- Update gate criteria to prevent recurrence

## Governance Rules (NON-NEGOTIABLE)

### Rule 1: No deployment without passing all gates
Every output must pass UI Agent → Tester → Reviewer → Chief Editor + CTO before reaching production. No exceptions.

### Rule 2: Every output goes through Tester/QA before reporting as complete
"Coder says it works" is not "it works." Tester/QA must verify before any output is reported complete.

### Rule 3: "Boil the ocean" standard
Only complete, impressive, tested, documented work counts. Half-baked outputs are failures. Every deployment must make Chris say "holy shit, that's done."

### Rule 4: Central coordination via tasks.md
All orchestras use the shared tasks.md for coordination. No orchestra-specific task files. No topic-hopping.

### Rule 5: Paperclip enforces sharing
Paperclip.ai scans for duplication automatically. If a component exists in Social Beast, use it. If an API pattern exists in KidScan, reuse it. No rebuilding what exists.

### Rule 6: Cost discipline
- Daily budget: Under $1 until revenue proven
- Default model: DeepSeek-chat (lowest cost)
- Flag any action >$10 for user approval
- Report token usage and cost in every evening report

### Rule 7: Memory discipline
- Compact memory every 4k tokens
- Daily notes in `memory/YYYY-MM-DD.md`
- Long-term memories in `MEMORY.md`
- Never lose valuable context
